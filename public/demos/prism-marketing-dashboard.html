RC Marketing Dashboard Handoff

What We Learned & What's Worth Borrowing

The RC dashboard (Ad Llama) is a Next.js 15 analytics tool for Ruskin Consulting. 187 Google Ads accounts, 146 BigQuery objects, 68 API routes, 25 per-account tabs. Here's what's relevant for Prism.

Design Patterns Worth Copying

UI and UX patterns RC uses that Prism should adopt or already has.

Eyebrows
Uppercase 10px labels above sections. Prism has them via .lbl — expand to all section headers.
Stats grid
Big number, letter-spaced label below. RC uses it on every major view. Now in Prism's Metrics and all 3 new tabs.
Token CSS
Everything through :root vars. Prism now matches this. Makes future theming or white-labelling trivial.
Data tables
RC's tabular data style — left-aligned text, right-aligned numbers, tabular-nums, subtle row hover. Now in Prism's Ads, Analytics, and Website tabs.
✨

Features Borrowed from RC

Directly ported from the RC handoff into Prism's new tabs.

Neg. push
Push negative keywords directly to Google Ads. RC's SearchTermReviewTab does this. Prism's Analytics tab has the same pattern with a "Push All Negatives" button.
Budget pace
Spend vs target bars per platform. RC tracks this cross-client. Prism shows Google Ads and Meta pacing in the Ads tab.
Wasted spend
RC's /waste route surfaces low-intent spend. Prism shows the same breakdown by category with spend amounts.
SEO grade
RC's SEO vertical (GSC + Ahrefs + PageSpeed + GA4). Prism's Website Analysis tab follows the same structure.
🏗

Architecture Lessons

How RC is built and what it means for Prism.

No live API
RC never calls ad platforms at render time. Everything pre-written to BigQuery by cron. Prism should cache ContentStudio and ad platform data server-side, not fetch on every page load.
Row-level SQL
RC's client auth scoping prepends a CTE in SQL. Right security boundary if Prism ever goes multi-client.
Service proxy
Both RC and Prism hold service keys server-side and expose allowlisted GET endpoints. Never leaks credentials to the browser.
Naming
RC's "three Llamas" confusion cost time. Prism should keep ContentStudio, OpenAI, Supabase clearly separated in env var names from day one.
⚠️

Gotchas RC Got Burned By

Specific bugs from the handoff. Don't repeat them.

Full-row writes
Supabase upserts replace the entire row. RC silently nulled fields for weeks. In Prism: always read, merge, then write.
Stale deploys
Railway env var changes can redeploy the old image. RC shipped stale for weeks. Always verify the build timestamp after deploy.
--ci flag
railway up --ci times out even when upload succeeds. Confirmed on Prism. Drop --ci, use railway up --service marketing-dashboard.
DATE params
Bound DATE params resolve to NULL in BigQuery multi-statement scripts. If SQL analytics are added: use CURRENT_DATE(), not bound params.
Bottom Line
RC and Prism share the same stack: Railway, Supabase, OpenAI, agency managing multiple clients. The most directly transferable things are the CSS token system (done), the service-proxy auth pattern (done), and the scheduled-pull data architecture. The three new Prism tabs — Ads, Analytics, Website — are direct ports of RC's /budget, /waste, and /seo verticals adapted for a content/marketing agency context.
